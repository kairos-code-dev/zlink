# 기술문서 작성 가이드

> 이 디렉터리는 기술문서를 작성·검토·개정할 때 따르는 규칙을 담는다. 주 독자는 문서
> 작업을 수행하는 AI다. 특정 제품이나 저장소 구조에 매이지 않은 작성 규칙만 둔다.

| 문서 | 언제 읽나 |
| --- | --- |
| [기술문서 작성 원칙](documentation-principles.ko.md) | 모든 기술문서에 공통으로 적용한다. 독자와 범위(원칙 1~2), 서술과 검증(3~6), 한글 산문 문체(7), 현재 상태 기술(8), 작성 후 리뷰(9). |
| [사용자 가이드 문서 작성 가이드](guide-writing-guide.ko.md) | 도입 판단과 사용법을 다루는 문서를 쓸 때 읽는다. |
| [스펙 문서 작성 가이드](spec-writing-guide.ko.md) | 공개 계약을 서술하는 문서를 쓸 때 읽는다. |

**세 문서의 관계.** 원칙이 상위이고, 두 작성 가이드가 문서 종류별 절차를 더한다. 두
가이드의 §2(작업 순서)·§3(용어 작성 규칙)은 같은 자리를 차지하되 문서 종류에 따라 다르게
규정한다 — 스펙은 계약을 정확히 서술하는 쪽으로, 사용자 가이드는 독자가 바로 판단하고
따라 쓰는 쪽으로 기운다.

**읽는 순서.** 원칙 1~9를 먼저 읽고, 쓰려는 문서 종류의 가이드를 읽은 뒤, 그 가이드의
완료 점검표로 마무리한다.
