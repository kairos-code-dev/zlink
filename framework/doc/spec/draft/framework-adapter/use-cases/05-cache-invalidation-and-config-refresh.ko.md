# Draft Use Case -- Cache Invalidation And Config Refresh

> 이 문서는 **구현 전 초안**이다.
> 현재 공개 계약이 아니며, 운영성 이벤트 use case를 정리하기 위한 초안이다.

## 1. 상황

일반적인 웹 서버와 게임 서버는 공통으로 아래 같은 운영성 이벤트를 자주 주고받는다.

- 캐시 무효화
- 설정 갱신
- 기능 플래그 변경
- 노드 상태 공지

이런 메시지는 보통 요청/응답보다 가볍고, 여러 인스턴스에 빨리 퍼지는 쪽이
중요하다.

## 2. 사용자가 기대하는 경험

- 관리 서비스가 이벤트를 한 번 발행하면 여러 인스턴스가 받는다.
- 각 인스턴스는 handler에서 로컬 캐시나 설정을 갱신한다.
- 같은 이벤트 이름에 대해 여러 모듈이 각각 구독할 수 있다.

## 3. 필요한 능력

- one-way event fan-out
- 다수 인스턴스 구독
- 가벼운 metadata
- 빠른 전파

## 4. 내부 매핑 초안

이 use case는 `PUB/SUB` 계열로 설명하는 것이 가장 자연스럽다.
다만 운영성 이벤트는 durable queue나 강한 재처리 보장까지 꼭 요구하지 않을 수
있다. 현재 초안은 우선 빠른 전파와 단순한 handler 모델에 집중한다.

## 5. 이 use case가 설계에 주는 요구

- event 모델은 비즈니스 도메인 이벤트뿐 아니라 운영성 이벤트도 무리 없이
  표현해야 한다.
- payload가 매우 작아도 과한 ceremony 없이 발행할 수 있어야 한다.
- 프레임워크 사용자는 "subscribe 하나 붙이면 된다"고 느껴야 한다.
