# `bindings/java` (+kotlin) POSD·DDD 리팩토링 통합 수정 목록

> 2026-07-08 `bindings/java/src/main/java/systems/zlink`(contracts ~7.2k + runtime ~24.7k, 237 타입) 전수 POSD/DDD 리뷰와 Codex 재검토 결과를 합친 통합 수정 목록. **kotlin 바인딩은 독립 라이브러리 소스가 없고 이 java 런타임을 그대로 공유**한다(kotlin은 `bindings/kotlin/samples`만 존재) — 따라서 이 문서가 kotlin에도 적용되며, dead 판정은 java+kotlin 양쪽 참조를 확인했다. 파일:라인은 리뷰 시점 기준이므로 편집 전 재확인한다. 공개 API 표면은 계약-잠금(E 제외). hot 항목은 커밋 전 baseline vs patched 벤치 필수.

위험 표기: **없음**(control plane) / **code-motion**(hot 경로 이동이나 명령 동일) / **벤치**(hot 구조에 닿음, 무회귀 증명 필수). 체크박스는 완료 시 갱신.

**공통 주의(리뷰에서 반복 확인됨):**
- `static { ContractAccess.register(...) }` bridge 블록은 JPMS 없이 runtime에 package-private 접근을 주는 **의도된 friend 관용구** — smell 아님, 건드리지 말 것.
- `ContractAccess.load("...Native"+"Runtime")` 식 문자열 분할 반사 로딩(`NativeMessageRuntime`, `NativeRuntimeFactory`, `NativeErrorRuntime`)은 의도적 — dead 아님.
- DONT_WAIT/nowait는 대개 같은 native 호출을 명시성 위해 분리한 것 — "blocking 버그"로 단정 말고 native 선언+주석 먼저 확인(cf. dotnet B4 오탐 전례).

**통합 검토 반영:**
- Codex 리뷰의 `ContractAccess.register(...)` 경계 지적은 최종 리팩토링 후보에서 제외한다. 현재 문서의 공통 주의처럼 JPMS export를 유지하면서 runtime이 contract-owned state를 채우는 의도된 friend bridge로 본다.
- Codex 리뷰의 routing-id layout 중복은 C8에 흡수한다. `SocketCore.java:739-789` callback/stream hot path에 닿으므로 static helper, inline-cache 보존, allocation-neutral 조건을 추가한다.
- Codex 리뷰의 `NativeRouterReceiveSupport.activeLazyReceive` dead state는 A0으로 채택한다.

## A. 삭제 트랙 (dead 코드/멤버)

- [x] **A0. `NativeRouterReceiveSupport.activeLazyReceive` 잔여 ThreadLocal 제거 검증** (**벤치**, high)
  - `NativeRouterReceiveSupport.java:52-58`에 `activeLazyReceive`와 completion runnable이 있지만, 같은 파일 안에 `activeLazyReceive.set(...)` 경로가 없다. `recvDirectOnceIntoImpl` 시작부(`:285-289`)와 일반 recv 시작부(`:416-429`)가 매번 `get/remove`를 수행한다.
  - `SpotRoutedSupport`와 `ReceivePlane`에는 실제 `set(...)` 경로가 있어 다른 파일로 일반화하면 안 된다. `NativeRouterReceiveSupport` 한정으로 제거 가능한지 테스트한다.
  - 제거가 맞다면 hot path의 ThreadLocal 접근과 분기를 줄이는 방향이다. 새 allocation/dispatch/lock 추가 금지.
  - 완료: `NativeRouterReceiveSupport` 한정으로 ThreadLocal과 completion runnable 전달을 제거했다. `SpotRoutedSupport`/`ReceivePlane`의 live ThreadLocal은 유지했다. `./gradlew compileJava --no-daemon` 통과.
- [x] **A1. `NativeSpot.drainChannelReply` + `drainChannelReplyFrom` 미완 스텁 — 설계 판단 후 처리** (없음, medium confidence)
  - `NativeSpot.java:495-517` package-private, 도달 불가(테스트 `SocketContractTest.java:474`가 public 아님을 assert로 고정). 단 이게 가드하는 `CHANNEL_REPLY_READABLE`/`CHANNEL_DEALER`는 실제 core 발행 이벤트+live codec(`EnumCodecs`)이 존재 → **미완 기능(channel/dealer reply drain)일 수 있음**. 맹목 삭제 말고 SpotRouteBridge/channel-dispatch 오너에게 "배선 완성 vs 폐기" 판단 의뢰.
  - 완료: `bindings/doc/spec/README.ko.md`가 `CHANNEL_REPLY_READABLE`을 readiness signal로만 정의하고 별도 public drain API를 금지한다. Java에는 `zlink_spot_drain_channel_reply` native 배선이 없고 `Spot` public surface 테스트도 drain API 부재를 고정하므로 private stub을 삭제했다.
- [x] **A2. `ZlinkException` dead plumbing 삭제** (없음, high) — `errno()`(38), `errorCode()`(42) package-private + `safeStrerror`(94) private. repo+kotlin 전역 무참조(자매 `safeErrno`만 live). 구식 strerror 메시지 설계 잔재.
- [x] **A3. `Native.requireSymbol` 미사용 wrapper 삭제** (없음, high) — `Native.java:25-27` private, 무참조. 감싸는 `NativeSymbols.require`는 live(내부 전용).
- [x] **A4. `NativeSpotNode.requireChannelName` 복붙 사본 삭제** (없음, high) — `NativeSpotNode.java:737-743`, 이 클래스엔 channelName 파라미터 메서드가 없어 도달 불가. live 사본 2개(`NativeSpot`/`NativeSpotRouteBridge`)는 유지(→ B/C 통합 후보로만).
- [x] **A5. dead ctor/변환기 정리** (없음) — `ZlinkConfigException`의 미사용 3-arg ctor(`ConfigResult,int,String` — 어떤 call site도 message 안 넘김, A2/C 예외 정리와 함께), `DurationConversions.toNativeTimeoutMillis`(무참조, C-nat 참조), `RoutedRequestSupport.toTimeoutInt` pass-through(`:115-117`, 4 caller를 `RequestReplySupport.toTimeoutInt` 직접호출로), `NativeErrorRuntime`의 dead static `errno()`/`strerror()`(`:26-32`).

## B. 결함 수정 (correctness — 리뷰 중 발견)

- [x] **B1. routed request 콜백 경로에 Java측 timeout backstop 누락** (없음, spec 확인 — **잠재 결함 최상위**)
  - `SpotRoutedRequestPlane.registerPendingCallback`(`:120-126`)에는 timeout 필드/스케줄이 아예 없어 native가 reply/timeout 콜백을 못 주면 `PENDING_CALLBACKS` 엔트리와 caller 콜백이 영영 안 불림. 자매 `SpotRequestPlane.registerDirectPending`(`:182-195`)는 `RequestReplySupport.scheduleRequestTimeout`로 보호됨. native `timeoutMs`가 routed callback 제출에 대해 항상 `TIMED_OUT`을 보장하는지 확인 후, 백스톱 추가 또는 부재를 의도로 문서화. C3 통합과 함께.
  - **추천 결정: 백스톱 추가(방어적).** 증상이 "콜백이 영영 안 불리는 hang"이라 심각도 높음 → native 보장이 미확인인 채 hang을 남기는 것보다 채널 경로(`SpotRequestPlane`)와 동일한 Java 백스톱을 추가하는 편이 안전(중복 타이머는 무해). C3(pending 레지스트리 통합)에서 백스톱을 균일 적용하면 자연 해소 → **C3와 묶어서** 진행. native가 authoritative로 확인되면 그때 백스톱을 의도적으로 제거.
  - 완료: `SpotRoutedRequestPlane`의 자체 callback pending 맵을 `RoutedRequestSupport.registerDirectPending`으로 교체해 동일한 timeout backstop을 적용했다. close 시 `TERMINATED` 완료도 공용 레지스트리를 통해 수행한다.
- [x] **B2. blocking send 재시도 errno 집합 divergence** (**벤치**, spec 확인)
  - `SocketSendPlane.sendMessageFrame(RoutingId,...)`(`:32-47`)는 `isTransientBlockingSendErrno`(EINTR/EAGAIN/EWOULDBLOCK_WIN/**ENOTCONN/EHOSTUNREACH**)로 재시도하는데, `send(byte[] routingIdBytes,...)`(`:64-84`)는 **EINTR만** 재시도하고 EAGAIN은 hard fail. 같은 "single-part blocking send"인데 정책이 갈림. native 계약으로 올바른 집합 확정 후 B-track 재시도 헬퍼(C6)로 통일. 관찰 가능한 timeout/retry 동작이 바뀌므로 맹목 병합 금지.
  - 완료: 기존 blocking send 정책 헬퍼 `isTransientBlockingSendErrno`를 `send(byte[] routingIdBytes,...)`에도 적용했다. 별도 retry policy는 새로 만들지 않았다.
- [x] **B3. 핸들러 등록 프로토콜 3가지 divergence 문서화/통일** (없음)
  - `SocketCallbackSupport.install`(재등록 매번) vs `NativeMonitorSocket.onEvent`(재등록 매번) vs `NativeRouterReceiveSupport.onReceive`(`:116-157`, `handlerRegistered` 가드로 **1회만** 등록 후 volatile handler swap). router는 hot path 최적화일 개연성이 크나 무주석 → 의도면 주석 명시, 아니면 `SocketCallbackSupport`에 "register-once + swap" 모드 추가해 정책 플래그화. router의 register-once를 "고치지" 말 것(안정된 native 콜백 포인터에 의존 가능).
  - 완료: `NativeRouterReceiveSupport.onReceive`에 register-once + Java handler swap 의도를 주석으로 고정했다. native handler 등록 정책은 변경하지 않았다.
- [x] **B4. `ZlinkException.fromErrno` op-이름 substring 분류 + dead branch** (없음)
  - `ZlinkException.java:56-84`가 caller op 문자열의 `containsAny`로 예외 타입 결정 → `:68`의 "request"가 `:80`의 "request"를 사장(dead). `actor_request_submit` 같은 미래 call site가 조용히 오분류될 함정. call site가 명시적 `ErrorCategory` enum을 넘기도록(`fromErrno(ErrorCategory, int)`) 전환, ~50 call site 1:1 교체.
  - 완료: `ErrorCategory` enum과 `fromLastError(ErrorCategory)`/`fromErrno(ErrorCategory, int)`를 추가했다. Java runtime 내부 호출부는 enum overload로 이동했고, `request`가 submit 분류에도 중복되던 dead branch는 제거했다. 기존 string overload는 공개 호환용으로만 남겼다.

## C. 구조 통합 — 지식 중복 소거 (없음/code-motion)

- [x] **C1. one-shot submit 빌더 상태기계 ~13벌 통합** (없음) — `submitted`+`ensureNotSubmitted`+`markSubmitted`+`parts`/`flags` 필드쌍이 `SpotActorJoinSupport`/`SpotActorJoinPlane`/`NativeActor`/`SpotNodeActorOperations`의 ~13 inner class에 verbatim. package-private `abstract SingleSubmitOperation` base로, 각 `submit()` 본문만 남김. native array 롤백 정확히 보존.
  - 완료: package-private `SingleSubmitOperation`이 submit 완료 여부, 메시지 부분 버퍼, 전송 flags 기본값과 `ensureNotSubmitted`/`markSubmitted`/`addPart`/`setFlags` helper를 소유한다. `SpotActorJoinSupport`, `SpotActorJoinPlane`, `NativeActor`, `SpotNodeActorOperations`의 submit builder가 이 base를 상속하도록 바꿨고, native array rollback은 기존 `submit()` 본문 안에 그대로 남겼다. 대상 파일 grep에서 기존 private 상태 필드와 private ensure/mark helper 중복이 사라졌고, `./gradlew test --no-daemon`이 통과했다.
- [x] **C2. actor join/leave 제출 프로토콜 node/actor 이중 구현 통합** (없음) — `SpotActorJoinPlane.ActorJoin/LeaveBuilder`(`:132-223,68-130`) ≡ `NativeActor.ActorJoin/LeaveBuilder`(`:190-270,304-359`), rid 출처만 차이. + `ActorJoinCallbackStage` pass-through wrapper가 두 파일에 literal 중복(+`SpotNodeActorOperations.RequestToActorCallbackBuilder` 세번째). 제출 본문을 `NodeSpotPair`/rid supplier로 파라미터화해 공유, pass-through stage 1벌화. **주의**: `NativeActor`가 submit 시점에 `node/spot.getRoutingId()`를 native 왕복으로 해석 — plane API의 명시 rid 인자와 동일 해석되는지(동시 `setRoutingId` 타이밍) 병합 전 확인.
  - 완료: `ActorJoinSubmitOperationBase`가 join 메시지 누적, timeout, flags, future 변환, pending 등록, native `spotNodeActorJoinSpot` 호출, 실패 시 native array rollback, progress pump 연결을 소유한다. `ActorLeaveOperationBase`가 leave timeout/future/pending/native submit skeleton을 소유한다. `SpotActorJoinPlane`은 명시 rid를, `NativeActor`는 기존처럼 submit 시점의 `node.getRoutingId()`/`spot.getRoutingId()`를 넘기도록 route hook만 구현한다. 두 파일의 `ActorJoinCallbackStage` 중복은 package-private `ActorJoinCallbackStage` 1개로 줄였고, `./gradlew test --no-daemon`이 통과했다.
- [x] **C3. request/reply pending 레지스트리 이중 구현 통합** (code-motion, B1과 함께) — `SpotRequestPlane`(채널) vs `SpotRoutedRequestPlane`(spot/router)가 `NEXT_REQUEST_ID`/`PENDING`/pending state/`upcallStub`/`close()` drain을 각자 구현(+ `ActorRequestCallbacks`가 세번째 패턴). `SpotPendingRequestRegistry<T>`로 추출하며 timeout 백스톱 균일 적용. **주의**: `SpotRequestPlane:303` HOT PATH 주석(콜백 경로는 Received/future 래핑 금지) 보존.
  - 완료: `SpotRoutedRequestPlane`은 자체 `NEXT_REQUEST_ID`/pending map/upcall stub을 제거하고 기존 `RoutedRequestSupport` 공용 레지스트리를 사용한다. `SpotRequestPlane`도 channel request용 `NEXT_REQUEST_ID`/pending map/upcall stub/direct pending state를 제거하고 `RoutedRequestSupport`의 request id, reply callback, pending/direct pending registry를 사용한다. `RoutedRequestSupport.registerDirectPending`이 channel/routed callback 양쪽의 Java timeout backstop을 소유하고, spot progress pump와 close 시 `TERMINATED` 완료는 유지했다.
  - 완료: `ActorRequestCallbacks`는 actor reply/join/join-entry/lookup/lifecycle별 ad hoc map과 반복 id 할당을 `ActorPendingRegistry<T>`로 통합했다. native callback signature와 result type은 서로 달라서 하나의 request/reply upcall로 합치지 않고, 공유 id allocator만 유지해 join callback의 generic reply fallback 충돌을 막았다. `./gradlew test --no-daemon` 통과.

## 핫패스 보존 게이트 (절대 위반 금지)

fast/no-alloc 단일프레임 수신 경로(`TopicPlane`/`NativeRouterReceiveSupport`의 HOT PATH 주석)·router register-once 콜백·`RequestCallState`류 단일 종료 게이트·요청 펌프 TCS/future 래핑 금지·pinned/GC-rooted native delegate·routing-id inline-cache fast path·DONT_WAIT 전용 native entry. **hot TU 변경(B2, C4, C6, C8, C11 일부)은 커밋 전 baseline vs patched 벤치 무회귀 증명, per-message 박싱/람다 캡처/iterator 할당 금지.**

## 권장 실행 순서

A(삭제) → B1·B2·B3·B4(결함) → C9·C10(errno/EINTR 기반) → C1·C2·C3·C5·C7(중복 통합) → D(기회순) → C4·C6·C8(벤치 게이트) 마지막. E는 별도 계약 트랙(dotnet과 공동 결정). kotlin은 java 런타임 공유라 별도 작업 불요, 단 D3/D4 인터페이스 변경 시 kotlin `when`/suspend 어댑터 컴파일 확인.
