# Kotlin YieldDispatch .NET 포팅 inventory

기준 구현은 `framework/languages/dotnet/e2e/YieldDispatch`이고, 공통 기준 문서는
`framework/doc/framework/common/e2e/config-8-yield-dispatch.ko.md`이다.
현재 Kotlin 구현은 `Shared`, `Client`, `Server/Delay`, `Server/Play`,
`Server/Session` Gradle module과 module별 binary로 delay/play/session/client를 실행한다.
registry role은 Redis location store 전환 뒤 제거했다.
stream endpoint와 session auth/relay runtime은 `Server/Session`으로 분리했다.

현재 Kotlin runner는 `logs/20260704-041428-16476`에서 `YD-A1`, `YD-A2`, `YD-A4`, `YD-B1`,
`YD-C1`, `YD-C2`, `YD-E1`, `YD-E2`, `YD-D1`, `YD-D2`, `YD-D3` marker와
module별 binary 실행을 확인한다. D2 전용 mode에서는 `play-b`도 추가 실행한다. `YD-A3`와
`YD-B2`는 공통 문서 의미에 맞춰 다시 정렬한 뒤 각각 `logs/20260707-222104-3660094`와
`logs/20260707-222754-3681782` focused runner에서 marker를 확인했다. `YD-B3`도 공통 문서 의미에
맞춰 다시 정렬한 뒤 `logs/20260707-224427-3751196` focused runner에서 marker를 확인했다. `YD-C1`과
`YD-C2`도 공통 문서 의미에 맞춰 다시 정렬한 뒤 각각 `logs/20260707-225303-3789894`와
`logs/20260707-225337-3792863` focused runner에서 marker를 확인했다. `YD-C3`도 공통 문서 의미에
맞춰 새 actor/timer 교차 scenario로 구현한 뒤 `logs/20260707-235604-4071087` focused runner에서
marker를 확인했다. `YD-E1`도 공통 문서 의미에
맞춰 다시 정렬한 뒤 `logs/20260707-230235-3830539` focused runner에서 marker를 확인했다. `YD-D2`와
`YD-D3`도 공통 문서 의미에 맞춰 다시 확인한 뒤 각각 `logs/20260707-231120-3878253`와
`logs/20260707-231217-3884460` focused runner에서 marker를 확인했다. `YD-D4`는
`logs/20260708-000440-4120944` focused runner와 `logs/20260708-000525-4125144` D1 aggregate runner에서
marker를 확인했다. `.NET` feature-map이 구현으로 표시한 항목 중 `YD-E3`는 아직 Kotlin에서 같은
수준으로 검증하지 않는다. `YD-E4`는 runner 정적 검사 일부만 추가했다. `.NET`도
`YD-E5` cross-language report aggregation은 부분 구현으로 남겼으므로,
Kotlin inventory에서도 완료로 과장하지 않는다.
